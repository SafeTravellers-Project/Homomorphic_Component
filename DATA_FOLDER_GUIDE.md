# Data Folder Structure and Usage Guide

This document describes the organization, purpose, and usage of data stored in the `data/` folder.

## Overview

The `data/` folder contains all cryptographic parameters, keys, and encrypted biometric data used by the Homomorphic Encryption biometric verification system. The folder is organized into five main subdirectories, each serving a specific role in the system's operation.

---

## Folder Structure

```
data/
├── System_Parameters/      # System-wide cryptographic parameters
├── Traveller/             # User/Traveller cryptographic keys
├── CountryDB/             # Registered biometric database
├── E-Gate/                # Test biometric data for verification
└── HEComp/                # Homomorphic computation keys
```

---

## 1. System_Parameters/

**Purpose**: Stores fundamental cryptographic parameters for both SEAL (BFV) and TFHE encryption schemes.

### Files:
| File | Description | Generated By | Used By |
|------|-------------|--------------|---------|
| `sealparam.txt` | SEAL BFV encryption parameters (N=4096, modulus={30,20,20,30}, p=20000) | HESysInit | Register, EncBio, Verify |
| `params_lwe_in.txt` | TFHE LWE parameters for input layer | HESysInit | Register, Verify |
| `params_lwe_out.txt` | TFHE LWE parameters for output layer | HESysInit | Verify |
| `params_tlwe_in.txt` | TFHE TLWE parameters for input layer | HESysInit | Verify |
| `params_tlwe_out.txt` | TFHE TLWE parameters for output layer | HESysInit | Verify |

**When Generated**: First time when running `HESysInit`

**Critical**: These files must exist before any other executable can run. They define the fundamental cryptographic scheme parameters.

---

## 2. Traveller/

**Purpose**: Stores cryptographic keys associated with the traveller/user. In a real-world deployment, each traveller would have their own set of keys.

### Files:
| File | Description | Size | Generated By | Used By |
|------|-------------|------|--------------|---------|
| `sealpubK.txt` | SEAL public key for encryption | ~8 KB | HESysInit | Register, EncBio |
| `sealpvtK.txt` | SEAL private key for decryption | ~8 KB | HESysInit | Verify |
| `sealrelinK.txt` | SEAL relinearization key for multiplication | ~1.5 MB | HESysInit | Verify |
| `lwe_in.txt` | TFHE LWE secret key (input) | ~32 KB | HESysInit | Register, Verify |
| `tlwe_in.txt` | TFHE TLWE secret key (input) | ~16 KB | HESysInit | Verify |
| `KSKmed.data` | TFHE key switching key (medium security) | ~520 MB | HESysInit | Verify |

**Security Note**: In production:
- Public keys (`sealpubK.txt`) can be shared
- Private keys (`sealpvtK.txt`, `lwe_in.txt`, `tlwe_in.txt`) must be kept secret
- The key switching key (`KSKmed.data`) is large due to TFHE's security requirements

---

## 3. CountryDB/

**Purpose**: Simulates the country's biometric database storing registered (enrolled) biometric templates.

### Structure:
```
CountryDB/
├── Test_Biometrics1              # Raw biometric template (example)
├── Test_Biometrics2              # Raw biometric template (example)
└── Reg_Biometrics_Enc/          # Encrypted registered biometric
    ├── ciph                      # Main encrypted biometric vector
    ├── sqciph                    # Encrypted squared values (for Euclidean distance)
    └── cosineciph                # Encrypted values for cosine similarity
```

### Files:
| File/Folder | Description | Format | Generated By | Used By |
|-------------|-------------|--------|--------------|---------|
| `Test_Biometrics1`, `Test_Biometrics2` | Raw biometric templates (examples) | 1024 float values (text) | Pre-existing | Register |
| `Reg_Biometrics_Enc/ciph` | Encrypted registered biometric vector | Binary (SEAL ciphertext) | Register | Verify |
| `Reg_Biometrics_Enc/sqciph` | Encrypted element-wise squares | Binary (SEAL ciphertext) | Register | Verify |
| `Reg_Biometrics_Enc/cosineciph` | Encrypted cosine similarity components | Binary (SEAL ciphertext) | Register | Verify |

**Usage Flow**:
1. Administrator provides raw biometric template file (e.g., `Test_Biometrics1`)
2. `Register` executable reads the raw file
3. `Register` encrypts and stores in `Reg_Biometrics_Enc/` folder
4. `Verify` executable reads encrypted data during verification

---

## 4. E-Gate/

**Purpose**: Stores test biometric data submitted by travellers at the E-Gate for verification.

### Structure:
```
E-Gate/
├── Example Tests/
│   ├── Test_Biometrics1          # Raw test template (same person)
│   └── Test_Biometrics2          # Raw test template (different person)
├── lwe_out2.txt                   # E-Gate's TFHE LWE key
└── Test_Biometrics_Enc/          # Encrypted test biometric
    ├── ciph                       # Main encrypted test vector
    ├── sqciph                     # Encrypted squared values
    └── cosineciph                 # Encrypted cosine components
```

### Files:
| File/Folder | Description | Format | Generated By | Used By |
|-------------|-------------|--------|--------------|---------|
| `Example Tests/Test_Biometrics*` | Raw test biometric templates | 1024 float values (text) | Pre-existing | EncBio |
| `lwe_out2.txt` | E-Gate TFHE LWE key | Binary (TFHE key) | HESysInit | EncBio, Verify |
| `Test_Biometrics_Enc/ciph` | Encrypted test biometric vector | Binary (SEAL ciphertext) | EncBio | Verify |
| `Test_Biometrics_Enc/sqciph` | Encrypted element-wise squares | Binary (SEAL ciphertext) | EncBio | Verify |
| `Test_Biometrics_Enc/cosineciph` | Encrypted cosine components | Binary (SEAL ciphertext) | EncBio | Verify |

**Usage Flow**:
1. Traveller provides test biometric at E-Gate
2. `EncBio` executable encrypts the biometric
3. Encrypted data stored in `Test_Biometrics_Enc/`
4. `Verify` compares against registered biometric

---

## 5. HEComp/

**Purpose**: Stores bootstrapping keys and intermediate computation keys for TFHE homomorphic operations.

### Files:
| File | Description | Size | Generated By | Used By |
|------|-------------|------|--------------|---------|
| `tgsw_out1.txt` | TFHE bootstrapping key (TGSW format) | ~16 MB | HESysInit | Verify |
| `lwe_out1.txt` | TFHE bootstrapping key (LWE samples) | ~32 KB | HESysInit | Verify |

**Technical Note**: 
- Bootstrapping keys enable TFHE to perform unlimited homomorphic operations
- Used during threshold comparison in the verification process
- Large size due to security requirements (noise refresh capability)

## Data Flow Through the System

```
1. HESysInit
   └─> Generates: System_Parameters/*, Traveller/*, HEComp/*, E-Gate/lwe_out2.txt

2. Register <raw_biometric>
   ├─> Reads: System_Parameters/sealparam.txt, Traveller/sealpubK.txt, lwe_in.txt
   └─> Generates: CountryDB/Reg_Biometrics_Enc/*

3. EncBio <test_biometric>
   ├─> Reads: System_Parameters/sealparam.txt, Traveller/sealpubK.txt, E-Gate/lwe_out2.txt
   └─> Generates: E-Gate/Test_Biometrics_Enc/*

4. Verify <threshold> <test_folder> <reg_folder>
   ├─> Reads: All System_Parameters/*, Traveller/* (except sealpubK.txt)
   │          HEComp/*, E-Gate/Test_Biometrics_Enc/*, CountryDB/Reg_Biometrics_Enc/*
   └─> Outputs: Accept/Reject decision
```

---

## File Format Specifications

### Raw Biometric Files
- **Format**: Plain text file
- **Content**: 1024 floating-point values (one per line)
- **Example**:
  ```
  0.123456
  0.789012
  0.345678
  ...
  (1024 total values)
  ```

### Encrypted Biometric Files
- **Format**: Binary files (SEAL ciphertext format)
- **Content**: Homomorphically encrypted polynomial coefficients
- **Cannot be read directly** - requires SEAL library and proper keys

### TFHE Key Files
- **Format**: Binary files (TFHE proprietary format)
- **Content**: LWE/TLWE samples and parameters
- **Large files** due to lattice-based cryptography requirements

|--------|-------------|-------|

| Traveller/ | ~520 MB | Dominated by KSKmed.data |
| CountryDB/ | ~100 KB per user | 3 encrypted files per registered user |
| E-Gate/ | ~100 KB per verification | 3 encrypted files per test |
| HEComp/ | ~16 MB | Bootstrapping keys |

**Total Initial Setup**: ~536 MB

## Security Considerations

### Public Data (Can be shared):
- `System_Parameters/*` - Encryption scheme parameters
- `Traveller/sealpubK.txt` - Public encryption key
- `CountryDB/Reg_Biometrics_Enc/*` - Encrypted biometrics (secure without keys)
- `E-Gate/Test_Biometrics_Enc/*` - Encrypted test data

### Private Data (Must be secured):
- `Traveller/sealpvtK.txt` - **Critical**: Enables decryption
- `Traveller/lwe_in.txt` - **Critical**: TFHE secret key
- `Traveller/tlwe_in.txt` - **Critical**: TFHE secret key
- `Traveller/KSKmed.data` - **Sensitive**: Key switching capability
- `HEComp/*` - **Sensitive**: Enables bootstrapping operations

## Troubleshooting

### Missing Files Error
**Symptom**: Executable fails with "file not found" or "cannot open file"

**Solution**:
1. Ensure `HESysInit` has been run successfully
2. Check that folder structure exists: `data/{System_Parameters, Traveller, HEComp, E-Gate, CountryDB}`
3. For registration: Verify raw biometric file exists in `CountryDB/`
4. For testing: Verify raw biometric file exists in `E-Gate/Example Tests/`

### Corrupted Data Files
**Symptom**: Verification produces unexpected results or crashes

**Solution**:
1. Delete all generated files: `rm -rf data/*/` (preserve folder structure)
2. Re-run complete flow: `HESysInit → Register → EncBio → Verify`

### Disk Space Issues
**Symptom**: System fails during key generation

**Solution**:
- Ensure at least 600 MB free space before running `HESysInit`
- `KSKmed.data` alone requires ~520 MB

---

## Best Practices

1. **Backup System_Parameters**: These files define your encryption scheme
2. **Never commit private keys to version control**: Add to `.gitignore`
3. **Regenerate test data**: Use different biometric samples for testing
4. **Clean encrypted data**: Remove old `*_Enc/` folders between test runs
5. **Verify folder permissions**: Ensure write access to `data/` subdirectories
